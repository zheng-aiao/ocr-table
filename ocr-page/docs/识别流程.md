# 珙县 OCR 识别流程说明

本文档描述 `ocr-page` 从抓拍到写出测点的完整识别链路，重点说明双屏路径、业务日期门禁、表格候选竞选，以及第三行（电价小数）的后处理规则。

> **设计原则：宁缺毋滥**  
> 业务日不猜、表头时刻不靠模板补列、空格不瞎填数值；异常格优先置空或强制重识，而不是编造。

---

## 1. 总览

```
摄像头 JPEG / 上传图 / 调试路径
        │
        ▼
┌───────────────────┐
│  入口 API / 定时  │  main.py · scheduler.py · pipeline*.py
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 0. 显示器区域裁剪 │  auto_monitor → 00_monitor.jpg
└─────────┬─────────┘
          │  (dual)
          ▼
┌───────────────────┐
│ 1. 左右分缝       │  auto_seam → left.jpg / right.jpg
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 2. 每侧独立 OCR   │  可 parallel_sides 并行
│   ├─ 业务日期 OCR │  失败则本侧跳过表格、不写 PI
│   └─ 表格 OCR     │  cameras.*.table_search 内 table_auto（失败本轮即止）
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 3. 组点 / 质量门  │  min_points；PI 日 = OCR 日 − pi_date_back_days
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 4. 落盘履历       │  data/ocr_runs/... + data/runs/...
└───────────────────┘
```

> **表格裁剪（现行）**：只做一轮 auto（可先缩到 `table_search`）。不像时刻表 → 本轮失败，**不再** fixed / 原图重识；等下一抓拍周期。  
> **弹窗蒙板（规则一致、门槛按侧）**：有出清弹窗必有灰蒙板 → `dimmed_modal` 快速失败。主信号「白纸弹窗 + 灰蒙」左右相同；`content/mean` 兜底门槛见 `cameras.*.modal_dim`（左正常偏暗≈145，右正常很亮≈210，不可共用）。关弹窗后下一轮再识。  
> **黑框 OSD**：显示器信号超范围等黑框覆在表上 → `black_osd` 快速失败（不硬识被挡表）。与蒙板不同：表区仍可能很亮，靠「实心近黑矩形 + 右侧亮表对比」检出。OSD 消失后下一轮再识。

|------|------|
| HTTP 路由 | `app/backend/main.py` |
| 单屏流水线 | `app/backend/pipeline.py` |

## 2. 入口与触发方式

| 入口 | 路由 / 调用 | 行为 |
|------|-------------|------|
| 单屏完整跑 | `POST /api/run` → `run_pipeline` | 抓拍 → OCR →（可选 Excel）→ PI |
| 双屏完整跑 | `POST /api/run/dual` → `run_pipeline_dual` | 抓拍 → 左右 OCR → PI |
| 仅 OCR（已有图） | `POST /api/ocr`、`/api/ocr/dual` | 不写 PI；`trigger=debug` |
| 上传识别 | `/api/ocr/upload`、`/api/ocr/dual/upload` | 临时文件；产物仍进 `ocr_runs` |
| 仅抓拍 | `POST /api/capture` | 只落盘抓拍图 |
| 按配置模式跑一轮 | `POST /api/schedule/run` | 跟随 `capture.mode` |
| 定时 | `scheduler.start_scheduler` | 开启后立刻一轮，结束后再等 `interval_sec` 秒 |

模式由 `capture.mode`（`single` | `dual`）决定。抓拍文件命名：

```text
data/captures/YYYYMMDD/H-MM.jpg
```

同分钟重复抓拍追加 `_2`、`_3`…

## 3. 双屏几何预处理

### 3.1 显示器区域（auto_monitor）

- 配置：`capture.dual.auto_monitor`（默认 `true`）；单屏未写时跟随 dual。
- 实现：`prepare_monitor_work_image` → `detect_monitor_region` / `apply_monitor_crop`。
- 失败或已近满屏：回退整图。
- 产物：`00_monitor.jpg`、`monitor.json`（含 structure / bright 等候选分）。

目的：远景四周有墙桌、或宽贴满但上下仍有环境时，先裁到显示器再分缝 / OCR。

### 3.2 左右分缝（auto_seam）

- 配置：`auto_seam`、`seam_fallback`（如 `0.55`）、`seam_gap`（如 `0.012`）。
- 纯 CV，通常 &lt; 50ms；在工作图宽度约 0.38–0.72 范围搜竖缝。
- 成功：覆盖左右半屏 crop；失败：用 `capture.dual.{left|right}.crop`。
- 产物：`seam.json`、`left.jpg`、`right.jpg`。

### 3.3 左右并行

- `ocr.parallel_sides: true` 时用线程池两侧同时跑。
- 每侧独立：`date_crop`、`table_crop`、`tag`、业务日、点数门槛。
- 允许一侧成功一侧失败（部分写 PI）。

## 4. 业务日期 OCR（门禁）

业务日**只**来自画面左上角「日期」筛选框的完整年月日 OCR，**不做**：

- 用本机日历 / API 入参猜日期
- 对侧成功则给本侧回填
- 缺少年月分隔时乱改月日数字

### 4.1 顺序

1. `resolve_business_date`（`ocr_bridge.py`）  
2. `extract_ui_date_from_image`：
   - `date_auto_locate=true`：先 `locate_date_filter_crop` 找「日期」标签，再裁右侧筛选框
   - **阶段 A**：自定位主框 + 邻域扩大框
   - **阶段 B**（A 全失败才走）：配置 `date_crop` + 邻域
   - 每框：原图通道 + 增强通道；认出完整 `YYYY-MM-DD` 立即成功
3. 失败 → `date_source=failed` → **本侧跳过表格 OCR**，不写 PI  
4. 成功 → 履历用 OCR 日历日；写 PI 时刻用：

```text
PI 业务日 = OCR 日期 − pi.pi_date_back_days   （默认 1，即提前一天）
```

### 4.2 日期产物（每侧目录）

| 文件 | 含义 |
|------|------|
| `date_locate.jpg` | 定位框（标签+筛选区） |
| `date_search_XX.jpg` | 搜索区域 |
| `date_crop.jpg` / `date_crop_enlarge_*.jpg` | 送入 OCR 的主框 / 扩大框 |
| `date_crop_cfg*.jpg` | 配置回退框 |
| `date_crop_best.jpg` | 本轮最佳 |
| `date_ocr.json` | 结构化结果（ok / date_str / attempts / reason） |

注意：日期裁剪**不做**表格那套纠偏（纠偏易把搜索框拉进曲线图 Y 轴刻度）。

## 5. 表格候选编排（ocr_bridge）

每侧在日期成功后进入 `extract_points_from_image`。

### 5.1 候选列表

1. **`table_fixed`**：配置 `table_crop`（相对半屏 / 工作图）
2. **`table_auto`**（可选）：`crop_ratio=None` → 蓝底表体自动定位并扩边（失败再落默认表带）

两路都是：裁剪 → 纠偏（deskew）→ 放大 → `TableImageExtractor.extract`。

### 5.2 竞选评分

元组（字典序越大越好）：

```text
(表头质量 hq, 实心行数 solid, 调整密度 dens_adj, -裁剪面积)
```

同分时**优先更紧裁剪**（面积更小）。

| 维度 | 计算要点 |
|------|----------|
| `hq` | 合法 Δ=15 时刻列得分；非法/回跳/坏间隔重罚；再扣前导空列、整型/小数混行罚分 |
| `solid` | 填格数 ≥ max(3, ⌈2n/3⌉) 的行数 |
| `dens_adj` | 填格百分比 + 原文带 ≥2 位小数的格子加分；超长「怪物格」扣分；混行再扣 |
| `-area` | 更紧的候选在同分时胜出 |

### 5.3 auto_enable

始终先跑 **fixed**。`ocr.auto_enable` 只决定 fixed 不够好时要不要再跑 **auto**：

- `true`：fixed 同时满足才跳过 auto，否则再跑 auto，两边都有结果时按分数择优
  - `hq ≥ 3`
  - 表头列数 ≥ 4
  - 电力/计划行（末行电价除外）不像摩尔纹假全 0
- `false`：只跑 fixed，不够好也不再跑 auto

### 5.4 胜出后

1. `_sanitize_headers_for_write`：丢掉非法时刻列，保留 Δ=15 锚段  
2. `_gap_fill_from_peer_candidates`：**只补空格**，用同表头其他候选已有值回填；不改已有值、不编造  
3. `_points_from_full_table`：按行标签 `tag_1/_2/_3` 组点  

产物：`cand_table_auto.jpg`、`cand_table_fixed.jpg`、`best_table.jpg`、`best_meta.txt`、`candidates.json`。

## 6. 单次表格提取内部流水线（extract_table）

`TableImageExtractor.extract` 对**一个**候选图的固定顺序：

| 步骤 | 函数 | 说明 |
|------|------|------|
| 1 | 比例裁 / `_resolve_table_auto_crop` | 得到表区 |
| 2 | `_deskew_table_image` | 蓝框 / 最小外接矩形 / Hough 纠偏 |
| 3 | `_scale_image_for_ocr` | `ocr.scale`、`max_ocr_width` |
| 4 | `_ocr_merge_multipass` | 多预处理通道 OCR，同位置优先保留**带小数点**的原文 |
| 5 | `_cluster_rows` | 按 Y 聚成行 |
| 6 | `_extract_header_info` 等 | 表头时刻；仅认 OCR 的 Δ=15 锚段，**不**用上午/下午模板补列 |
| 7 | `_find_main_data_row` + `_merge_fragmented_data_rows` | 主数据行与碎片合并 |
| 8 | `_build_full_matrix` | 建成 表头 × 数据矩阵 |
| 9 | `_postprocess_rows` | `_fix_decimal_ocr`、漏点补救（识别原文原样保留，不因量级置空） |
| 10 | 末行按 X 重对齐 | 再跑一遍 `_fix_decimal_ocr` |
| 11 | `_fill_sparse_data_row` | 用主数据行 OCR 填末行空格 |
| 12 | `_refill_matrix_empties` | 空格局部再 OCR |
| 13 | `_reocr_suspicious_price_cells` | 电价可疑已填格强制重识（可覆盖错值） |
| 14 | `_trim_trailing_empty_and_broken_headers` | 裁掉尾部坏列 |
| 15 | `_enforce_expected_data_rows` | 数据行硬封顶 **3** 行 |
| 16 | `_untangle_integer_decimal_rows` | 整型/小数混行拆开 |
| 17 | `_repair_price_row_lost_dots` | 4 位无点在 `xx.xx` / `x.xxx` 间按同行锚点选优 |

业务表体约定：

```text
1 行时刻表头 + 3 行数据
  行1：省内实时中标电力（整型为主）
  行2：实时发电计划（整型为主）
  行3：省内实时中标电价（小数为主）← 本文「第三行」
```

## 7. 第三行（电价小数）专项

### 7.1 与第 1、2 行的差异

| 行为 | 第 1、2 行（电力 / 计划） | 第 3 行（电价） |
|------|---------------------------|-----------------|
| 内容特征 | 多为整数 | 多为带小数点 |
| 量级置空 | **已去掉**：识别到什么就展示什么；写 PI 时由 `pi.value_max` 限制 | 同左 |
| `_fix_decimal_ocr` | 同样应用到单元格 | 已带 `.` 的串**原样保留** |
| `_repair_price_row_lost_dots` | 一般无带点锚点则不触发 | 无点 4 位在 `xx.xx` / `x.xxx` 间按锚点选优，都不像则保留原文 |
| `_reocr_suspicious_price_cells` | — | 无点 4 位 / 整数部过长疑似串列 → 强制重识 |
| `_untangle_integer_decimal_rows` | 渗出的小数抽走 | 小数行沉底；已有小数优先保留 |

### 7.2 `_fix_decimal_ocr`（格式恢复，不是改数字）

对**整段无小数点**的数字串：

| 条件 | 行为 |
|------|------|
| 已有 `.` | **原样返回**（真实识别路径） |
| 6 位 | `xxx.xxx`（如 `281451` → `281.451`） |
| 7 位 | 试去首/尾后按 6 位，且数值落在约 50–999 |
| 5 位 | `head3≥200` → `xxx.xx`；`head2≤25` → `xx.xxx`；否则 `xxx.xx` |
| **≤2 位** | **不插点，保持原文** |
| 3 位且在电价行 | 竖纹抑制后重识；仅当 `xx.x` / `x.xx` 明显更靠近左右邻格才改（如 `152`→`15.2`）。对不上邻格保持原文 |

含义：不再把短残缺串硬凑成小数；但无点的 5/6 位仍会按电价常见格式「补点」。补的是小数点位置，**不会改 OCR 读出的各位数字**。

### 7.3 `_repair_price_row_lost_dots`

- 仅处理 `-?\d{4}`，在 `xx.xx` 与 `x.xxx` 之间选（`1205` 在同行约 15 时 → `12.05`；同行约 3 时 → `1.205`）
- 得分与 5 位相同：相对左右邻格和同行中位数的最小相对误差；最优超过 `ratio_k` 则不改
- 两候选接近时按同行小数位数众数破平；无锚点不猜，保留原文

### 7.4 混行拆分 `_untangle_integer_decimal_rows`

斜拍 / 粘连时小数会渗进第 2 行、整数渗进第 3 行：

1. 按小数占比找「电价行」，必要时沉到矩阵末行  
2. 逐列：上方行里的小数抽到电价行；电价行已有小数优先保留  
3. 整型池回填上方空格  

### 7.5 当前**不猜**的内容（与小数相关）

- 空格用邻列/历史曲线外推猜数值（gap 只从**其他候选已 OCR 出的同列表头**补空）
- 把 2 位无点整数硬插成小数（`67`→`6.7`）
- 3 位无点在对不上左右邻格时硬插点（`111` 不会被改成 `11.1`）
- 电价行因「位数众数」批量删格
- 已带小数点的 OCR 原文被后处理改掉各位数字

仍存在的「非猜值、但是启发式」：

- 无点 5/6 位的**小数点位置**恢复  
- 有锚点时的 4 位漏点补救（`xx.xx` / `x.xxx` 二选一）  
- 可疑格局部重识（以新 OCR 覆盖旧值）

## 8. 质量门与写 PI

1. 每侧有效点数 ≥ `ocr.min_points`（默认 8），否则本侧失败、不写 PI。  
2. 测点前缀：`capture.dual.left.tag` / `right.tag`（或 single.tag）→ `前缀_1` / `_2` / `_3` 对应三行。  
3. 时刻戳：表头 `HH:MM` + PI 业务日（OCR 日回退 `pi_date_back_days`）。  
4. `trigger=debug` / OCR-only：`pi.skipped=true, reason=ocr_only`。  
5. 正式写入可开 `pi.verify_write` 回读校验。

### 8.1 跨轮众数计票（已公布时段）

电价按 15 分钟公布；分钟级多次抓拍下，**最后一次 OCR 写库**可能被单次误识别改坏。正式写 PI 前对质量门已过的点做众数：

| 条件 | 行为 |
|------|------|
| 本机时间 ≥ 表头时刻 | 计入 `data/vote_tallies/YYYYMMDD.json`；写 PI 用当前次数最多的值（1 票也可胜出；后续真值票多会覆盖） |
| 本机时间 < 表头时刻 | 预测段，不计票，OCR 值直通写库/展示 |
| 空值 / 无效解析 / 本侧未达 `min_points` | 不计票 |
| OCR-only / 联调不写 PI | 不记票（避免污染） |

- 页面表格仍展示**本轮 OCR**；详情页悬停单元格可看历史候选值与票数排名（`GET /api/votes?day=`）。  
- 配置：`ocr.vote.enabled` / `ocr.vote.dir`。  
- 实现：`app/backend/vote_store.py`，双摄流水线写 PI 前调用。

## 9. 产物目录结构

根目录：`ocr.artifacts_dir`（默认 `data/ocr_runs`），按日分区与 `captures` 一致：`ocr_runs/YYYYMMDD/<YYYYMMDD_HHMMSS_mmm>/`。

### 双屏 / 双摄：`YYYYMMDD/<YYYYMMDD_HHMMSS_mmm>/`

```text
00_source.jpg          # 原图拷贝
00_monitor.jpg         # 显示器裁剪结果
monitor.json
seam.json
left.jpg / right.jpg
left/
  date_locate.jpg, date_crop.jpg, date_crop_best.jpg, date_ocr.json, ...
  cand_table_auto.jpg, cand_table_fixed.jpg
  best_table.jpg, best_meta.txt, candidates.json
right/
  （同上）

```

履历副本：`data/runs/YYYYMMDD/<ts>.json`（页面履历读取；兼容旧 `mode_<ts>.json` / 扁平 `runs/*.json`）。

静态访问：`/data/ocr_runs/...`、`/ocr_runs/...`。

## 11. 端到端时序（双屏正式跑）

```text
run_pipeline_dual
  ├─ 摄像头抓拍 → data/captures/...
  ├─ split_and_ocr
  │    ├─ prepare_monitor_work_image
  │    ├─ detect_dual_seam → seam_to_side_crops
  │    └─ _ocr_one_side × 2（可并行）
  │         ├─ extract_ui_date_from_image
  │         │    失败 → 空结果，跳过表
  │         └─ extract_points_from_image
  │              ├─ cand table_auto.extract
  │              ├─ [必要时] cand table_fixed.extract
  │              ├─ _score 竞选 + peer gap_fill
  │              └─ 组 points（PI 日回退）
  ├─ evaluate_ocr_point_count
  ├─ apply_majority_votes（已公布计票；预测直通；OCR-only 不记票）
  ├─ [非 ocr_only] write_points_to_pi（写众数胜出值）
  └─ persist_pipeline_result → run.json + data/runs/YYYYMMDD/（含 vote 快照）
```

单屏去掉分缝与左右目录，其余日期门禁 + 表格候选逻辑相同。

## 12. 已知问题与案例（第三行）

案例轮次：`dual_20261014_153834_479`（抓拍 `15-38.jpg`）。

画面真值（节选）与结果对比：

| 侧 | 时刻 | OCR 结果 | 画面真值 |
|----|------|----------|----------|
| 左 | 01:15 | **08.673** | 330.867 |
| 右 | 02:15 | **16.659** | 166.591 |
| 右 | 02:30 | **12.090** | 209.093 |
| 右 | 03:15 | **09.816** | 109.816 |

补充现象：

- 左屏 **auto** 候选里 01:15 曾认出正确的 `330.867`，但竞选因「表头/实心/密度同分、fixed 裁剪更紧」选了 **fixed**，错值进终结果。  
- `gap_filled=0`：这些错不是空格猜填，而是 OCR 读错或无点 5 位被插成错误量级。  
- 例：无点 `16659` → `_fix_decimal_ocr` 的 `head2≤25` 规则 → `16.659`。  
- 已带点的错误值（如 `08.673`）因电价行不清洗、且不一定命中「可疑格」重识条件，会直接落盘。

### 根因归纳

1. 引擎对电价格**字面误读**（缺位、错位）。  
2. 无点 5 位格式补点可产生「看起来像小数、量级却错」的结果。  
3. 异常值不再后处理置空；写 PI 仅靠 `pi.value_max` 卡上限。  
4. 候选分不直接衡量电价正确性 → 更紧但更错的候选可能压过更对的 auto。

### 可能改进方向（未实现，仅记录）

- 竞选：电价行量级突变 / 与 peer 候选差异过大时扣分  
- 已带点但相对同行中位极端偏离的格：强制局部重识或置空  
- 无点 5 位插点前增加更严的量级/邻格一致性校验  
- auto 回退 / 同分策略：不要仅因裁剪更紧牺牲电价正确候选

## 13. 调试建议

6. 改 `config.yaml` 后需重启服务（`ocr.bat restart`）再生效。
